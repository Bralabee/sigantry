# PR-bot migration in v3.0

> Stub migration doc. The Sigantry PR-review bot is a brand-new feature
> shipped with the v3.0.0 release; there is **no migration needed
> from v2.x** -- the bot did not exist in earlier versions.

## What's new in v3.0 for the PR-bot

The bot ships as the 17th top-level Typer subapp on `sigantry`:

```bash
sigantry pr-bot run --provider auto --pr-id <id> --token <token> \
  --base-dir <dir> --head-dir <dir>
```

It is invoked from a CI workflow on PR open / synchronize. There is no
daemon, no GitHub App webhook listener, no ADO Service Hook
subscription. See [the operator runbook](../runbooks/pr-bot-operator.md)
for end-to-end setup.

## v2.x -> v3.0 caveats that affect the PR-bot

While there is no migration FROM the v2 bot (it never existed), the
v3.0 shim that let v2.x adopters continue importing
`fabric_dataops_toolkits` affects the PR-bot's pinning (that shim was
dropped in v3.1, so on v3.1+ only the new name resolves at all):

- The bot's CLI lives at `sigantry pr-bot run`. The legacy
  `fabric_dataops_toolkits` package does NOT expose this subcommand.
- Adopters consuming v3.0 must depend on the new `sigantry-core`
  PyPI distribution (formerly `fabric-dataops-toolkits`):

  ```toml
  # pyproject.toml
  [project]
  dependencies = [
    "sigantry-core>=3.0",
  ]
  ```

The shim's lifetime — one minor release, v3.0 only — is documented in
[ADR-0011: Rename to Sigantry](../decisions/ADR-0011-rename-to-sigantry.md).

## Adopting the bot in an existing repo

Adopters on v2.x who want to enable the PR-bot should:

1. Update their `pyproject.toml` (or `requirements.txt`) to depend on
   `sigantry-core>=3.0` (drop or pin alongside any
   `fabric-dataops-toolkits` reference per the shim ADR).
2. Copy `templates/starter/.github/workflows/pr-bot.yml` (GitHub) or
   `templates/starter/.azuredevops/jobs/pr-bot.yml` (ADO) into their
   repo as documented in the [operator runbook](../runbooks/pr-bot-operator.md#enabling-the-bot-in-your-repo-github).
3. Push a test PR with a TMDL change and confirm the bot comment
   appears.

No code changes to existing v2.x deploy / governance / monitoring
plugins are required to enable the bot -- it is additive.
